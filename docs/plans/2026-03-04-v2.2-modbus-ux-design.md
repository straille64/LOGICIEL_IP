# V2.2 Modbus UX — Design Document

**Date:** 2026-03-04
**Scope:** Quadrillage du tableau principal + Refonte popup de détails (édition dynamique complète)

---

## Objectifs

1. **Quadrillage** du tableau principal des registres (lignes alternées + séparateur de colonne)
2. **Popup de détails** : suppression de la ligne ASCII, tous les champs restants deviennent éditables
3. **Synchronisation dynamique** : modifier n'importe quel champ recalcule tous les autres en temps réel, sans boucle infinie
4. **Bits cliquables** : les 32 checkboxes de bits deviennent interactifs

---

## Partie 1 — Quadrillage du Treeview principal

### Contrainte

`ttk.Treeview` ne supporte pas nativement les séparateurs de colonnes. Deux mécanismes sont combinés.

### Mécanisme 1 : Alternance de couleurs par ligne

Dans `_populate_table`, tag chaque ligne selon sa parité :

```python
tag = "oddrow" if row_index % 2 else "evenrow"
self.tree.insert("", END, values=(...), tags=(tag,))
```

Configuration des tags via `ttk.Style` ou `tree.tag_configure` :

```python
self.tree.tag_configure("oddrow",  background="#2b2b2b")  # darkly theme
self.tree.tag_configure("evenrow", background="#323232")
```

### Mécanisme 2 : Séparateur de colonne visuel

Ajouter une 3e colonne `"sep"` de largeur 2px avec fond contrastant :

```python
self.tree["columns"] = ("reg", "sep", "val")
self.tree.column("sep", width=2, minwidth=2, stretch=False)
self.tree.heading("sep", text="")
# La couleur de fond du frame parent (sombre) sert de "bordure"
```

Dans `_populate_table`, toujours insérer `""` dans la colonne "sep".

### Fichiers modifiés

- `modules/tab_modbus.py` — `_build_right_panel`, `_populate_table`

## Partie 2 — Refonte de la popup RegisterDetailDialog

### Suppressions

- La ligne **ASCII** (4 cellules) est supprimée du tableau
- Les constantes `fmt_ascii_byte` restent dans le fichier (utilisées ailleurs potentiellement) mais ne sont plus appelées depuis la popup

### Layout final de la grille (5 lignes)

| Ligne | Col 0 (label) | Octet 3 | Octet 2 | Octet 1 | Octet 0 |
|-------|--------------|---------|---------|---------|---------|
| 1 | **Binaire** | `Entry` 8 chars | `Entry` 8 chars | `Entry` 8 chars | `Entry` 8 chars |
| 2 | **Octet** | `Entry` 3 chars | `Entry` 3 chars | `Entry` 3 chars | `Entry` 3 chars |
| 3 | **Mot 16** | `Entry` colspan 2 | | `Entry` colspan 2 | |
| 4 | **Mot 32** | `Entry` colspan 4 | | | |
| 5 | **Réel 32** | `Entry` colspan 4 | | | |

### Bits cliquables

Les 32 checkboxes passent de `state=DISABLED` à `state=NORMAL`.
Chaque checkbox a un `command=lambda bit=bit: self._on_bit_click(bit)`.

### Options (inchangées)

Panneau droit : Hexa, Non signé, Inv. Octets, Inv. Mots
→ Chaque case appelle `_refresh()` (pas `_on_change`) car elles ne modifient pas les données brutes, seulement la présentation.

## Partie 3 — Architecture anti-boucle

### Source de vérité unique

`self._w0: int` et `self._w1: int` — les deux registres 16 bits bruts (0–65535).
Toute modification d'un champ met d'abord à jour `_w0`/`_w1`, puis appelle `_refresh()`.

### Flag `_updating`

```python
self._updating: bool = False
```

### Flux de synchronisation

```
User modifie champ X (trace_add "write" ou command bit)
  → _on_change(source=X)
      if self._updating: return          # anti-boucle
      self._updating = True
      try:
          val = parse(champ X)           # peut lever ValueError
          update _w0 / _w1 selon X
          self._refresh()                # écrit TOUS les StringVars
      except ValueError:
          pass                           # saisie incomplète, ignorer
      finally:
          self._updating = False
```

### Parsers par type de champ

| Champ source | Parser | Impact sur _w0/_w1 |
|---|---|---|
| Binaire[i] (8 bits) | `int(text, 2)` → byte (0-255) | Injecter dans le bon octet de `_w0` ou `_w1` |
| Octet[i] | `int(text, 0)` clamp 0-255 | Idem |
| Mot 16 hi (w0) | `int(text, 0)` clamp 0-65535 | `_w0 = val` |
| Mot 16 lo (w1) | `int(text, 0)` clamp 0-65535 | `_w1 = val` |
| Mot 32 | `int(text, 0)` clamp 0-0xFFFFFFFF | `_w0 = val >> 16`, `_w1 = val & 0xFFFF` |
| Réel 32 | `float(text)` → `struct.pack(">f")` → 4 bytes | `_w0 = bytes[0:2]`, `_w1 = bytes[2:4]` |
| Bit checkbox[i] | toggle bit i | `_w0 ^= (1 << i)` ou `_w1 ^= (1 << (i-16))` |

### Note sur swap_words dans les parsers

Quand `swap_words=True`, Mot 16 "hi" affiché = `_w1` réel.
Les parsers doivent tenir compte du swap pour écrire dans le bon registre.

```python
if swap_words:
    word_hi_attr, word_lo_attr = "_w1", "_w0"
else:
    word_hi_attr, word_lo_attr = "_w0", "_w1"
```

### `_refresh()` — logique inchangée

`_refresh()` lit `_w0`/`_w1`, calcule toutes les dérivées, écrit les StringVars/BooleanVars.
Puisque `_updating=True` pendant son appel, les `trace_add` des Entry sont bloqués — aucune boucle.

## Partie 4 — Structure des Entry et leurs callbacks

### StringVars pour les Entry éditables

```python
# Binaire : 4 StringVar pour les 4 octets
self._bin_vars: list[tk.StringVar] = [tk.StringVar() for _ in range(4)]

# Octet : 4 StringVar
self._oct_vars: list[tk.StringVar] = [tk.StringVar() for _ in range(4)]

# Mot 16 : 2 StringVar (hi et lo selon swap_words)
self._mot16_vars: list[tk.StringVar] = [tk.StringVar(), tk.StringVar()]

# Mot 32 : 1 StringVar
self._mot32_var: tk.StringVar = tk.StringVar()

# Réel 32 : 1 StringVar
self._reel32_var: tk.StringVar = tk.StringVar()
```

### Bindings

```python
# Pour chaque StringVar sv avec source identifier src:
sv.trace_add("write", lambda *_, s=src: self._on_change(s))

# Pour chaque bit checkbox:
command=lambda b=bit: self._on_bit_click(b)
```
